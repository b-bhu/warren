# How to Write Milestones

Read this document before creating or changing any milestone.

A milestone describes a meaningful product outcome for the user. It should explain what becomes possible when the milestone is complete, without turning into a technical plan or a long feature wishlist.

## Principles

- Focus on one clear user outcome.
- Describe the experience in plain language.
- Keep the scope small enough to finish and demonstrate end to end.
- Define completion through observable user behavior.
- State what is excluded so the milestone does not quietly expand.
- Avoid implementation details, providers, protocols, frameworks, and architecture.
- Leave detailed requirements and technical decisions for the PRD.

## Milestone Format

### Outcome

One sentence describing what the user will be able to accomplish.

### Why It Matters

The user problem this milestone solves and why it is worth solving now.

### User Experience

A short description of the journey from the user's starting point to the completed outcome.

### Included

The minimum product capabilities required to deliver the outcome.

### Complete When

A small set of observable conditions proving that the milestone works end to end.

### Not Included

Related ideas intentionally postponed to later milestones.

## Final Check

Before accepting a milestone, ask:

1. Does it solve one recognizable user problem?
2. Can a real user complete the journey from beginning to end?
3. Can we clearly demonstrate that it works?
4. Is every included capability necessary for the stated outcome?
5. Are future ideas explicitly kept out of scope?
